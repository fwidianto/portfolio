# Homepage V2 Representative Experiment

Status: Frozen revised experiment brief / pre-concept-refinement checkpoint

Date: 2026-08-02

This document defines the representative surface used to test the selected external frontend skills. It has been revised so the portfolio is judged primarily through the **Analytical Systems Builder** identity lens.

No frontend implementation is authorised by this document.

## Experiment Question

Can the selected frontend skills create a mature, distinctive, recruiter-friendly homepage first screen that makes visitors understand—through structure and evidence, not only through a title—that Fauzan is an **Analytical Systems Builder**?

The result must preserve the existing static architecture, use only approved content, and avoid rebuilding the full website.

## Identity Standard

Read:

`docs/design/analytical-systems-builder-identity-lens.md`

The homepage must embody:

```text
Analytical
= investigate complexity, validate evidence, and structure ambiguity

Systems
= understand flows, dependencies, handoffs, and end-to-end consequences

Builder
= turn understanding into practical tools, workflows, interfaces, and operating systems
```

The visible narrative should feel like:

```text
messy reality
-> structured understanding
-> connected system
-> usable outcome
```

The identity must remain understandable even if the words `Analytical Systems Builder` are temporarily hidden.

## Current Baseline

The current homepage first screen contains:

- fixed navigation with `FW.` and links to Project, Experience, Skills, Thinking, and Contact;
- the role label `Analytical Systems Builder`;
- the headline `From problems and data to system design, insights, and AI-powered workflows.`;
- a general introduction about curiosity, projects, tools, and AI-assisted experimentation;
- four similarly weighted actions;
- a profile card with portrait, name, role, and three summary metrics;
- an immediate transition into the current Odoo project section.

The current code uses static HTML, CSS, and JavaScript. The experiment must continue from this architecture.

## Baseline Weaknesses to Test

1. The current profile-card and metric treatment resembles a generic portfolio template.
2. Four similarly weighted buttons weaken the primary visitor path.
3. The introduction does not state practical professional value directly enough.
4. The hero does not yet express analytical reasoning or system relationships.
5. The transition introduces only Odoo and does not establish the complementary role of Telegram Codex Controller.
6. The visitor must work too hard to understand how analysis, systems thinking, and building connect.
7. Motion and responsiveness have not yet been designed as part of the professional narrative.

## Exact Representative Surface

The experiment is limited to:

```text
existing navigation
+ homepage first viewport
+ a visible transition into the next section
```

The transition may preview the two approved projects. It must not implement the full project section or determine the final structure of the complete homepage.

Required viewports:

- desktop: approximately `1440 x 900`, with a purposeful glimpse of the next section;
- tablet: approximately `768 x 1024`;
- mobile: approximately `390 x 844`.

## Target Visitor Understanding

### Within 5 seconds

The visitor should understand:

> Fauzan turns complex operational problems and data into understandable systems and practical workflows.

### Within 10-15 seconds

The visitor should understand:

1. he investigates and structures complexity;
2. he sees connected systems rather than isolated tasks;
3. he builds usable outcomes;
4. the portfolio offers two complementary proof paths:
   - business and ERP operating systems;
   - controlled AI-assisted work systems.

### Desired feeling

The screen should feel:

- mature;
- calm;
- intelligent;
- credible;
- structured;
- quietly distinctive;
- human;
- operational rather than decorative.

It should not feel like a developer template, futuristic AI dashboard, consultancy imitation, game interface, or generic data portfolio.

## How the First Screen Must Express the Identity

### Analytical

The first screen should show:

- a clear problem-to-understanding progression;
- precise hierarchy and reading order;
- restrained evidence rather than decorative metrics;
- language focused on understanding, review, and action.

### Systems

The first screen should show:

- one connected visual logic;
- meaningful pathways, rails, lines, or transitions;
- two projects as different systems inside one worldview;
- continuity between the hero and the next-section preview.

### Builder

The first screen should show:

- analysis moving toward practical outcomes;
- project descriptions focused on what became usable;
- a clear action path toward real evidence;
- stable outcomes rather than endless animated activity.

## Elements to Preserve

- Fauzan's real name and current portrait as a human anchor;
- the `Analytical Systems Builder` identity;
- the existing headline;
- access to CV, LinkedIn, and GitHub;
- the existing static-site architecture;
- a professional connection to the current warm, calm, business-oriented portfolio;
- semantic headings, readable contrast, visible focus, and reduced-motion support.

The portrait may be reframed and does not need to remain in the circular profile card.

## Elements Allowed to Change

- first-screen composition;
- portrait placement and framing;
- action hierarchy;
- use of lines, pathways, rails, stages, or system-map motifs;
- spacing, type scale, and container rhythm;
- header visual treatment while preserving current labels and destinations;
- the two-project transition treatment;
- subtle animation and hover states that clarify sequence, connection, or state;
- responsive re-routing of system paths.

## Prohibited Elements

Do not add:

- additional or supporting projects;
- fake metrics, outcomes, clients, users, or claims;
- dark mode or a theme toggle;
- a literal interactive world map;
- dashboard charts in the hero;
- terminal windows or code-editor imagery as the main identity;
- decorative pills, floating widgets, or badges without information value;
- a new navigation architecture;
- a framework, build system, or deployment migration;
- full downstream homepage sections;
- continuous floating, glowing, pulsing, rotating, or bouncing animation.

The existing `6+`, `ERP`, and `BI` hero metrics should be omitted unless the owner later approves a clearly superior, factual, non-template use.

## Concept Direction A — Living System Editorial

Foundation:

```text
Editorial / Casebook structure
+ Dieter Rams restraint
+ Systems Canvas connection motif
```

Expected character:

- strongest recruiter readability;
- calm, precise typography;
- purposeful whitespace;
- portrait used as human editorial evidence;
- one clear primary action;
- a subtle analytical-to-system-to-outcome sequence;
- visible connection to both project paths.

This is the safer baseline and should score highly on professional credibility.

## Concept Direction B — Living World Interface

Foundation:

```text
professional editorial base
+ subtle connected-destination interface
+ restrained spatial or navigational cues
```

Expected character:

- the first screen feels like an entrance into one connected professional world;
- the two projects appear as destinations inside one system;
- stronger systems expression than Option A;
- no literal map, game UI, futuristic control room, or neon treatment.

This remains a useful stress test for how expressive the Living World metaphor can become without weakening credibility.

## Preferred Refinement Direction

The next refinement should begin from:

```text
Option A clarity and editorial foundation
+ only the strongest connection cues from Option B
```

Do not combine every visual element from both options. Borrow only cues that materially improve systems coherence.

## Motion Requirements

Motion must explain the identity.

Recommended uses:

- staged hero reveal following the reading order;
- a path reveal from problem to system to usable outcome;
- project-path emphasis on hover or focus;
- a section-transition cue that visually connects the hero to the two systems;
- motion that settles into a stable state.

Reject motion that is decorative, constant, distracting, or delays access to information.

Support `prefers-reduced-motion` with a complete static equivalent.

## Responsive Requirements

### Desktop

- may show the complete relationship between identity, reasoning sequence, portrait, and two project paths;
- should include a purposeful glimpse of the transition below.

### Tablet

- requires a deliberate intermediate composition;
- pathways should re-route or simplify rather than merely shrink;
- portrait and text hierarchy must remain balanced.

### Mobile

- becomes a clear vertical narrative:

```text
identity
-> value
-> analytical/system sequence
-> two proof paths
-> evidence action
```

- connection graphics should simplify to a vertical rail or staged progression;
- project paths must not become generic cards;
- actions must remain clear and touch-friendly;
- no horizontal overflow.

## Concept Deliverables

1. desktop concept;
2. tablet concept;
3. mobile concept;
4. motion-state description or lightweight motion storyboard;
5. reduced-motion state;
6. comparison against the previous concepts;
7. scorecard using the identity and design criteria below.

Do not concept the entire website.

## Approval Scorecard

Score each category from 1 to 5. Every category must score at least 4 before implementation.

| Category | Approval question |
| --- | --- |
| Analytical clarity | Is the problem-solving value understandable without relying only on the title? |
| Systems coherence | Does the screen feel like one connected system? |
| Builder evidence | Does analysis clearly lead to practical outcomes? |
| Professional credibility | Is the design mature enough for recruiters and managers? |
| Responsive preservation | Does each viewport preserve the identity and narrative? |
| Motion purpose | Does every animation explain sequence, connection, state, or direction? |

## Owner Review Questions

1. Would a visitor infer `Analytical Systems Builder` even without seeing the title?
2. Is the professional value understandable within 5 seconds?
3. Does the design visibly connect analysis, systems thinking, and building?
4. Do the two projects feel distinct but part of one professional identity?
5. Is the portrait treatment credible and human?
6. Does the Living System metaphor clarify rather than decorate?
7. Is the screen distinctive without becoming flashy?
8. Does animation explain the system rather than merely add movement?
9. Does tablet feel intentionally designed?
10. Does mobile preserve the connected narrative rather than become stacked cards?
11. Can the concept be implemented faithfully in the current static site?
