# UI/UX Direction for Portfolio Refresh

## Purpose

This file defines the visual and user-experience direction for the portfolio refresh.

The portfolio should help recruiters, hiring teams, and collaborators quickly understand Fauzan's capability as a data/business analytics-oriented professional with operations experience and AI-assisted workflow exposure.

## Design Goal

Create a modern, clean, professional analytics portfolio.

The design should feel:

- Clear
- Modern
- Recruiter-friendly
- Analytical
- Practical
- Professional
- Easy to scan
- Mobile-friendly

It should not feel:

- Overly decorative
- Too developer-terminal focused
- Too generic
- Too academic
- Too crowded
- Too experimental for job hunting

## UX Principle

Clarity before decoration.

The site should answer these questions quickly:

1. Who is Fauzan?
2. What type of roles is he suitable for?
3. What capabilities can he demonstrate?
4. What projects prove those capabilities?
5. How can a recruiter view his CV, GitHub, LinkedIn, or contact him?

## Homepage Recommended Structure

1. Hero
2. Capability Snapshot
3. Featured Projects
4. Selected Experience
5. Tools & Skills
6. About / Working Style
7. Contact CTA

## Hero Section Direction

The hero should communicate the updated positioning within a few seconds.

Recommended wording direction:

```text
Data & Business Analytics Professional
Turning business data, operational processes, and AI-assisted workflows into clearer insights and decision support.
```

The hero should include clear actions:

- View Projects
- Download CV
- GitHub
- LinkedIn

## Capability Snapshot Direction

Show 3-4 capability areas before listing projects.

Recommended capability groups:

### Data Analysis & Insights

Finding patterns, drivers, anomalies, and business implications from operational and business data.

### Dashboard & Reporting

Building dashboards and reporting workflows for management visibility and decision support.

### Business Process Understanding

Connecting data with real workflows across operations, sales, procurement, finance, inventory, and ERP systems.

### AI-Assisted Workflow

Using tools such as ChatGPT, Codex, and automation platforms to accelerate documentation, analysis, and project delivery.

## Project Section Direction

Project cards should be scannable and consistent.

Each card should show:

- Project title
- One-sentence value proposition
- Tags
- 2-3 proof bullets
- Safe links such as Case Study, GitHub, or Demo

Project cards should not be long paragraphs.

Featured project order should prioritize job-relevant proof:

1. Odoo ERP Analytics Platform
2. AI ERP Intelligence Dashboard
3. Business Reporting Automation
4. PersonalOS / AI Handoff Workflow
5. HS Code Trade Compliance Automation
6. Investment Analytics Dashboard
7. MCU Vault

## Project Detail Page Direction

Project pages should read like compact case studies.

Use the structure from `PROJECT_TEMPLATE.md`.

Make each page easy to scan with:

- Clear headings
- Short paragraphs
- Bullets where useful
- Visual proof only when public-safe
- A confidentiality note where necessary

## Visual Style Direction

Recommended style:

```text
Modern dashboard-inspired portfolio
```

Design characteristics:

- Clean background
- Strong typography hierarchy
- Generous spacing
- Card-based project layout
- Subtle borders or shadows
- Consistent accent color
- Clear buttons
- Responsive layout
- Minimal visual noise

Avoid heavy animation or complex effects unless they improve clarity.

## Typography Direction

Use clear, readable typography.

Prioritize:

- Strong hero heading
- Clear section headings
- Comfortable paragraph length
- Good line height
- Strong contrast
- Easy mobile reading

## Color Direction

Use a professional palette.

Recommended feel:

- Neutral background
- Dark readable text
- One main accent color
- Subtle secondary tones for cards, tags, and dividers

Do not use too many bright colors.

## Layout Direction

Use a responsive layout that works well on:

- Mobile phone
- Tablet
- Laptop
- Desktop monitor

Recommended layout patterns:

- Single-column flow on mobile
- Two-column hero or project layout on wider screens
- Grid cards for projects
- Sticky or simple top navigation if it improves usability

## Navigation Direction

Navigation should be simple.

Recommended navigation:

- Home
- Projects
- Experience
- About
- CV
- Contact

If the site is single-page, use anchors. If the site has project detail pages, keep navigation consistent across pages.

## Content Density Direction

The homepage should not contain every detail.

Recommended depth:

- Homepage: quick summary and proof previews
- Project cards: concise proof
- Project pages: deeper case-study detail
- GitHub: technical evidence
- CV: formal career record

## Mobile Direction

Mobile must be treated as important.

Check:

- Hero text does not feel cramped
- Buttons are easy to tap
- Cards stack cleanly
- Navigation is usable
- Project detail pages remain readable
- No horizontal scrolling

## Performance Direction

Keep the site lightweight.

Avoid adding unnecessary frameworks, large libraries, or heavy animation packages unless approved.

## Accessibility Direction

Minimum expectations:

- Good text contrast
- Buttons and links are visually clear
- Images have meaningful alt text where possible
- Layout works without relying only on color
- Font sizes are readable on mobile

## Acceptance Criteria

The UI/UX refresh is successful when:

- A recruiter can understand the profile within 30 seconds.
- The portfolio looks professional on desktop and mobile.
- Project cards are easy to scan.
- Project detail pages are readable.
- Visual design supports data/business analytics positioning.
- The site does not feel like a generic developer template.
- No confidential material is displayed.
- The implementation remains lightweight and maintainable.
