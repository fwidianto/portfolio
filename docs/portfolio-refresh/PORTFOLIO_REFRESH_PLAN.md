# Portfolio Refresh Plan

## Objective

Refresh the public portfolio so it reflects the current professional direction:

> Business operations and ERP analytics professional building AI-assisted data systems, SQL reporting layers, automation workflows, and decision-support dashboards from real operational ERP data.

The portfolio should support applications for:

- Business Intelligence Analyst
- Data Analyst
- Business Operations Analyst
- FP&A / Revenue / Planning Analyst
- Strategy & Operations Analyst
- Digital Transformation / Automation Specialist
- ERP Analytics / Reporting Analyst

## Current state

The portfolio is functional and clean, but its public story is behind the current progress.

Current positioning emphasizes:

- Business Operations & ERP Analyst
- ERP migration support
- Profitability simulation
- Executive dashboards

This is still true, but it does not fully show recent work in:

- Odoo Analytics / `dashboard-odoo`
- SQL-based Odoo reporting
- Operational data modeling
- AI-assisted coding workflow with ChatGPT and Codex
- AI ERP Intelligence Dashboard
- PersonalOS / CareerOS / AI handoff workflow
- Career-focused analytics portfolio direction

## Target positioning

Recommended homepage title:

> Business Operations & ERP Analytics Specialist

Recommended subtitle:

> Bridging ERP systems, SQL-based analytics, automation, and AI-assisted development to turn operational data into decision-ready business intelligence.

Alternative title options:

1. `Business Operations & ERP Analytics Specialist`
2. `ERP Analytics & Business Intelligence Analyst`
3. `Business Operations Analyst | ERP, BI & Automation`

Recommended default: option 1.

## Core message

The portfolio should tell this story:

1. The user understands real business operations, not just dashboards.
2. The user has practical ERP experience with SAP and Odoo.
3. The user can translate messy operational flows into structured reports.
4. The user can work with SQL, Python, Flask, dashboards, and automation.
5. The user uses AI-assisted development responsibly to accelerate implementation.
6. The user is strongest at the intersection of business process, data, and decision support.

## Project case study recommendations

### Odoo ERP Analytics Platform

Purpose:

Build an analytics layer on top of Odoo operational data to improve management visibility across sales, purchasing, inventory, invoicing, profitability, and traceability.

Public-safe description:

- SQL-based analytical views.
- Odoo PostgreSQL source data.
- SO/IO traceability concept.
- Dashboard-ready metrics.
- Business rule validation.
- Reporting replacement for manual Excel workflows.

Do not expose:

- Real Odoo data.
- Company-sensitive field values.
- Credentials.
- Customer/supplier/order details.

### AI ERP Intelligence Dashboard

Purpose:

A deployed Flask dashboard that demonstrates ERP-style analytics, table exploration, SQL query interface, and AI-assisted reporting concepts.

Public-safe description:

- Flask/Python web app.
- SQLite / sample or sanitized data.
- Customer/product/supplier analytics.
- Query interface.
- Dashboard navigation.
- Deployed demo link.

### Business Reporting Automation

Purpose:

Show business value from Excel, Google Sheets, Apps Script, VBA, UiPath, and Looker Studio work.

Public-safe description:

- Reduced manual reporting effort.
- Improved visibility and review flow.
- Dashboard and automation support for management decisions.

### PersonalOS / AI Handoff Workflow

Purpose:

Show the user's systems thinking and AI workflow maturity without exposing private content.

Public-safe description:

- Private Markdown-based knowledge system.
- CareerOS, Project Hub, AI Handoff, templates.
- Reduces repeated context setting between ChatGPT, Codex, GitHub, and local files.
- Supports documentation-driven AI-assisted development.

### HS Code Trade Compliance Automation

Purpose:

Show browser automation and data extraction capability.

Public-safe description:

- Playwright automation.
- INSW portal data extraction concept.
- Excel/JSON output.
- Import compliance research support.

### Investment Analytics Dashboard

Purpose:

Show dashboarding, market data presentation, and personal analytics.

Public-safe description:

- Google Sheets / Apps Script / Looker Studio.
- TradingView widgets.
- Allocation tracking.
- Market monitoring.

## Acceptance criteria

The refresh is successful if a recruiter can understand within 30 seconds:

1. What the user does.
2. What business problems the user solves.
3. Which tools and systems the user uses.
4. Which projects prove the claims.
5. Why the user fits analytics, BI, ERP reporting, operations, or transformation roles.
