# Project Documentation Template

Use this template for every major portfolio project.

The goal is to make each project easy for recruiters to understand while proving analytical thinking, business understanding, dashboard/reporting capability, operations experience, automation mindset, and AI-assisted workflow exposure.

## Project Name

Clear project name.

Example:

```text
Odoo ERP Analytics Platform
```

## One-Line Summary

Explain the project in one sentence.

Recommended format:

```text
Built / designed / developed [solution] to help [user/business] solve [problem].
```

Example:

```text
Built an analytics layer on top of Odoo ERP data to improve visibility across sales, procurement, inventory, invoicing, and profitability workflows.
```

## Context

Explain the background.

Questions to answer:

- Why did this project exist?
- What problem or opportunity triggered it?
- Was it related to work, personal learning, automation, analytics, or portfolio development?
- What business or operational process does it connect to?

## Problem

Explain the specific problem.

Good problem statements may include:

- scattered data
- manual reporting
- poor visibility
- slow analysis
- unclear profitability
- hard-to-track workflows
- repetitive work
- inconsistent documentation
- difficulty connecting business process and data

## My Role

Explain what Fauzan did using honest wording.

Good examples:

- Designed the analytical structure
- Defined business logic
- Built or assisted the build using AI-assisted coding
- Created dashboards or reporting workflows
- Validated data logic
- Documented process and findings
- Translated business questions into data structure, reporting logic, or workflow improvements

Avoid overclaiming as a pure software engineer if the work was AI-assisted or primarily analytical.

## Tools & Technologies

Group tools by purpose.

Example:

- Data: SQL, PostgreSQL, SQLite
- Analytics: Python, Looker Studio, spreadsheets
- Systems: Odoo, SAP, ERP data
- Automation: VBA, Apps Script, UiPath
- AI workflow: ChatGPT, Codex, OpenHands
- Web/demo: Flask, GitHub Pages, HTML, CSS, JavaScript

Only include tools that are actually relevant to the project.

## Workflow / Approach

Explain how the project works.

Possible structure:

1. Data source
2. Cleaning / transformation
3. Business logic
4. Output / dashboard / report
5. Review or decision-support usage

Keep this understandable for recruiters. Technical details can be included, but they should support the business story.

## Key Features

List 3-6 important features.

Example:

- Sales order traceability
- Profitability monitoring
- Dashboard-ready analytical tables
- Automated reporting workflow
- Public-safe demo using sample data

## Business / Analytical Value

Explain why the project matters.

Focus on:

- better visibility
- faster reporting
- clearer decision support
- reduced manual work
- improved data structure
- better understanding of business processes
- ability to connect operational details with management-level insights

Avoid unsupported quantified impact unless the source files explicitly support it and the detail is public-safe.

## What This Project Demonstrates

Connect the project to job-relevant capabilities.

Example:

```text
This project demonstrates business analysis, data modeling, dashboard thinking, ERP process understanding, and AI-assisted workflow execution.
```

## Relevant Roles

List roles this project supports.

Example:

- Data Analyst
- Business Analyst
- BI Analyst
- Operations Analyst
- Digital Transformation Analyst
- Automation Analyst

## Screenshots / Demo

Use only public-safe screenshots, mock data, sample data, or sanitized visuals.

Do not show private raw notes, internal business records, real internal-party names, confidential financial details, secrets, or private links.

## Links

Add links only when safe:

- Live demo
- GitHub repo
- Case study page
- CV reference

## Limitations / Confidentiality

Be transparent about what cannot be shown.

Example:

```text
Some business logic and internal data cannot be displayed publicly due to confidentiality. The portfolio version uses generalized descriptions, sanitized screenshots, or sample data.
```

## Recommended Project Card Format

Use this shorter format for homepage and project listing cards:

```text
Project Title
One-sentence value proposition.

Tags: SQL · Python · Dashboard · ERP · Automation

Proof bullets:
- Problem solved or workflow improved
- Analytical/business capability demonstrated
- Output or result created

Links: Case Study · GitHub · Demo
```
