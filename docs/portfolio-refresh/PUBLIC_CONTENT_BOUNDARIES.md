# Public Content Boundaries

This portfolio repository is public. Treat every change as recruiter-facing and internet-facing.

## Safe to publish

The portfolio may include:

- Public professional summary.
- Public project names and high-level descriptions.
- Links to public repositories.
- Public deployed demo links.
- Sanitized screenshots that do not expose confidential business data.
- Technology stack summaries.
- High-level architecture diagrams.
- Public-safe case studies that describe business problems, solution approach, and impact.
- AI-assisted development workflow at a high level.

## Do not publish

Do not publish:

- Private PersonalOS files or raw personal notes.
- Job application tracker details.
- Interview notes or recruiter communication.
- Salary expectations or negotiation notes.
- Company-sensitive data from PT Nobi Putra Angkasa or previous employers.
- Real Odoo credentials, database names, tokens, API keys, or connection strings.
- Internal customer, supplier, employee, invoice, purchase order, sales order, or operational data.
- Screenshots containing confidential ERP records.
- Private family, health, or personal reflections.
- Any material that makes the user look like a software engineer if the work is actually AI-assisted analytics implementation.

## How to reference PersonalOS safely

PersonalOS should be presented as a concept or private workflow, not exposed as a full public repository.

Recommended public framing:

> PersonalOS is a private Markdown-based knowledge and workflow system for organizing career strategy, project documentation, AI handoffs, reusable prompts, and long-term learning.

Safe details:

- It uses Markdown as the source format.
- It separates knowledge base, career planning, project hub, AI handoff, templates, archive, and daily workflow.
- It helps reduce repeated context-setting when working with ChatGPT, Codex, GitHub, and local project files.

Avoid:

- Listing private file contents.
- Mentioning sensitive personal categories in detail.
- Publishing private career evaluations or job application records.
- Copying source-of-truth files directly.

## How to present AI-assisted work

Use honest wording:

- `AI-assisted development`
- `AI pair programming`
- `SQL and Python implementation supported by AI tools`
- `Business-led analytics development using AI coding agents`

Avoid overstating:

- Do not claim to be a full-stack software engineer.
- Do not imply all code was written manually from scratch.
- Do not hide the business-analysis ownership behind technical jargon.

Preferred framing:

> I define the business logic, validate the data behavior, design the reporting requirements, and use AI-assisted coding workflows to accelerate implementation.
