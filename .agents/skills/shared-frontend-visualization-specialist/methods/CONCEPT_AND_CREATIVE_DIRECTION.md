# Ariadne Method — Concept and Creative Direction

**Use when:** a frontend task introduces or materially changes visual direction, page rhythm, featured-project identity, signature motion, or a major representative section.

## Objective

Separate creative exploration from implementation so the Builder does not code the first plausible idea and rationalize it afterward.

## Process

1. State the design problem: audience, desired understanding/action, distinctive quality, familiar/protected behavior, and non-scope.
2. Mine the project's real visual material: artifacts/documents, states, transitions, handoffs, branches, convergence, inputs/outputs, exceptions/recovery, and public-safe evidence.
3. For novel work, generate at least three genuinely distinct concepts before selecting one. Each concept states composition, primary visual artifact, section rhythm, motion thesis, project specificity, implementation complexity, and responsive behavior.
4. Run the genericity test: if the exact visual/motion could be renamed and reused for an unrelated project with almost no change, it is not specific enough for a signature moment.
5. Create enough concept evidence to judge the complete approved surface before coding. Use readable section concepts rather than one compressed full-page image when detail would be lost.
6. Extract a small design system: palette, typography, spacing, container model, borders/radii/strokes, icons/media, motion timing/meaning, repeated components, responsive rules.
7. Once owner/project authority accepts the concept, treat it as an implementation specification. Material reinterpretation returns to the owner/orchestrator.

## Motion identity questions

For a featured project:

1. What moves in the real or represented system?
2. What changes state?
3. What branches, converges, waits, fails, or resolves?
4. What does the visitor learn by watching it?
5. Why would this motion be wrong for a different project?
6. What is the reduced-motion equivalent?

## Semantic economy

Do not encode the same meaning twice without a reason. If animation already communicates direction, a static arrow must add separate meaning or be removed. If layout already establishes hierarchy, decorative labels must justify themselves.
